build:

```text
AIProvider
   │
   ├── generate()
   ├── stream()
   ├── structuredOutput()
   ├── embed()
   └── capabilities()
```

Then a provider can advertise capabilities.

For example:

```text
Gemini
 ├── Text generation       ✓
 ├── Streaming             ✓
 ├── Structured output     ✓
 ├── Embeddings            ✓
 └── Vision                ✓

Ollama
 ├── Text generation       ✓
 ├── Streaming             ✓
 ├── Structured output     ✓
 ├── Embeddings            ✓
 └── Vision                depends on model
```

That becomes **very useful later** when you add Life Library with YouTube/video/images and eventually multimodal AI.

---

### One important practical choice

For your **local DB**, I'd use:

**PostgreSQL + pgvector + Redis + local filesystem initially.**

I would **not** add MongoDB, Supabase, Pinecone, Qdrant, Weaviate, etc. right now.

You already have PostgreSQL/pgvector knowledge, and keeping the entire data layer together makes this project much easier to reason about.

The end result can become a genuinely substantial project:

**Next.js + TypeScript + PostgreSQL + pgvector + Redis/BullMQ + RAG + Gemini + provider abstraction + agents + memory + OAuth integrations.**

That is considerably more valuable as an engineering project than simply making five separate AI demos.
